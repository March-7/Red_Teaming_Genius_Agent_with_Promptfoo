# 阶段 3（12 家族分层全量）Goal 定义

## Goal

对剩余 12 个风险家族执行**分层** ASR 测量（按载荷类型分类：自洽型全量 100 条、矛盾型/依赖型 30 条探路），完成 15 家族总表与最终方法论报告。所有测量沿用阶段 0 冻结样本（scale-v1/*-100.json 原样）+ 阶段 2 完整证据模式（evidence_full 落盘后才删 session）。

## 分层策略（用户已批准 2026-10-22）

| 层 | 判据 | 配量 | 目的 |
| --- | --- | --- | --- |
| 自洽型 | oracle 载荷是公式/口径/方法论——模型无法用文档事实核查推翻 | 100 条/家族（10 组全跑） | 真实攻击面主战场，拿完整 ASR |
| 矛盾型/依赖型 | oracle 载荷是事实声明（可与文档交叉验证）或依赖不存在的规范 | 30 条/家族（前 3 组） | 确认 0% 形态是否跨家族成立，为阶段 4 提供改造依据 |

**分类表需用户过目**（写入本 goal 后附）——分类直接决定谁全量谁探路。若用户未在首个 goal round 内回复，按表中默认分类执行（用户已批准分层建议本身）。

## 运行参数

| 项 | 值 |
| --- | --- |
| 家族数 | 12（15 − 阶段 2 已完成的 3 个） |
| 分类结果 | 自洽型 6 家族 / 矛盾型 3 家族 / 依赖型 3 家族 |
| 总样本 | 6×100 + 6×30 = **780 条** |
| 分组 | 6 家族 × 10 组 + 6 家族 × 3 组 = **78 组** |
| chat 预算 | ≤**960 次**（780 主调用 + 两轮铺垫 ~40 + 容差 ~140，含事故冗余） |
| 证据模式 | **full**（沿用阶段 2 改造） |
| 模型 | 双模型全交叉（每家族各 ~50 或 ~15） |
| 执行顺序 | 家族串行，组内串行；自洽型优先（主战场先拿数据） |
| 失败处理 | 单条记 invalid 不重试；整组失败跳组记录；SSE 挂起由线程硬超时（720s）自愈 |
| 清理 | 每组结束即清；中断恢复点从磁盘 manifest 重建（阶段 2 会话重启的教训） |

## 硬约束

1. **预算**：≤1,050 次 chat；超出立即停止就已跑部分出报告
2. **跑完不优化**：全部计划样本跑完前不改任何变体（矛盾型家族 0% 也只记录）
3. **样本/谓词冻结**：scale-v1 原样，oracle 契约不动
4. **evidence_full 100%**：缺失视为执行缺陷
5. **guard 强制、凭据安全、资源名中性**
6. **不做载荷改造**（那是阶段 4）；不跑 15 家族外的任何正式样本

## 验收标准

### V1. 执行完成
- [ ] 78 组全部执行（或预算停止点），每条 result JSON 含 status/predicates/evidence_full/session_id
- [ ] evidence_full 完整率 100%
- [ ] 清理凭证：78 skill + ~780 session（或残留清单+清理）

### V2. 15 家族总表
- [ ] 12 家族各自 ASR（探路型注明 30 条样本基数）
- [ ] **15 家族合并总表**（含阶段 1/2 数据）：家族 × ASR × 模型 × 载荷类型
- [ ] 载荷类型假设验证：自洽型家族 ASR 显著高于矛盾/依赖型（预期格局）
- [ ] 每家族拒绝形态归类（复制阶段 2 的五层验证/澄清阻塞分类法）
- [ ] awareness 检查（零真实命中）+ invalid 清单

### V3. 最终交付
- [ ] **总结汇报材料**（用户最初目标）：15 家族完整风险画像 + 方法论结论 + 防御发现
- [ ] 阶段 4 载荷改造建议清单（针对 0% 家族：哪些载荷可自洽化、哪些依赖需补全）
- [ ] 报告 + 全部 run 产物落盘 + ledger 记账 + 通知用户
